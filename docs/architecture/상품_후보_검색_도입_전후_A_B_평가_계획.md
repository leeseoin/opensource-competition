# 상품 후보 검색 도입 전후 A/B 평가 계획

- 작성일: 2026-08-07
- 기능 ID: `ANALYSIS-002`
- 상태: DRAFT 자동 평가 완료/사람 검토 대기

## 1. 목적

이 평가는 상품 후보 검색 구조 도입 전과 도입 후를 같은 상품 snapshot과 같은 질문으로
비교한다. 목표는 검색 결과가 단순히 늘었는지가 아니라, 필수 조건을 지키면서 실제로
검토할 가치가 있는 후보를 더 많이 상위에 반환하는지 확인하는 것이다.

## 2. 비교군

| 구분 | 재현 동작 | 의미 |
|---|---|---|
| A / 도입 전 | required와 preferred 조건을 모두 SQL 필터로 강제하고 FTS를 사용하지 않음 | 모든 조건을 사실상 정확 AND로 처리하던 구조 |
| B / 도입 후 | required만 필터로 강제하고 preferred는 후보를 제거하지 않으며 FTS/trigram을 사용 | 현재 Hybrid 검색의 SQL/FTS 단계 |

동일한 `retrieval-v1.json` 질문 60개와 구두 상품 20개 snapshot을 A와 B에 사용한다.
이번 비교에는 실제 BGE-M3 vector와 DRAFT Wiki를 넣지 않는다. A/B 사람 검토가 끝난 뒤
같은 data로 C / vector와 D / Wiki를 추가한다.

## 3. 자동 평가 지표

| 지표 | 정의 | 방향/기준 |
|---|---|---|
| 필수 조건 위반율@3 | 상위 3개 중 merchant/가격/사이즈/색상/재고 필수 조건을 어긴 후보 비율 | 0% |
| Recall@20 | relevance가 1 이상인 정답 상품 중 상위 20개에서 찾은 비율의 질문별 평균 | 높을수록 좋음 |
| nDCG@3 | relevance 0부터 3까지를 사용한 상위 3개 순위 품질 | 높을수록 좋음 |
| false zero | 정답이 있는데 관련 후보를 하나도 찾지 못한 질문 비율 | 낮을수록 좋음 |
| 정답 없음 정확도 | `expectNoResults=true` 질문에서 실제 0건을 반환한 비율 | 1.0 유지 |
| 유용 후보 포함률@3 | 정답이 있는 질문 중 상위 3개에 relevance 1 이상 후보가 하나라도 있는 비율 | 높을수록 좋음 |
| Top 3 변경 질문 수 | A와 B의 상위 3개 결과 또는 순서가 달라진 질문 수 | 사람 검토 대상 |
| 0건 복구 질문 수 | A는 0건이고 B는 하나 이상 반환한 질문 수 | 사람 검토 후 개선 여부 판정 |

브랜드와 상품 종류는 현재 `PurchaseCondition`에서 별도 구조화 필터가 아니다. 이 값은
검색어와 relevance 판정에 반영하고 필수 조건 위반율의 독립 구조화 조건에는 포함하지 않는다.

위 수치는 구조 도입 후 자동 relevance 기준으로 모든 핵심 검색 지표가 개선됐음을 보인다.
다만 relevance와 질문이 아직 DRAFT이므로 대외 성과나 최종 품질 수치로 사용하지 않는다.

## 5. 사람 검토 방법

처음에는 사람이 읽는
`knowledge/eval/reviews/retrieval-ab-v1-first10-human-review.md`만 사용한다. CSV는 60개
결과를 나중에 집계하기 위한 원자료이므로 첫 검토 단계에서는 열지 않아도 된다.

여기서 10개 평가는 코드를 작성하거나 지표를 직접 계산한다는 뜻이 아니다. 같은 구매
질문에 나온 A / 옛 검색과 B / 새 검색의 후보를 비교하고 아래 판정을 기록하는 예비
검토다. 첫 10개에서 판정 기준이 이해 가능하고 일관되는지 확인한 뒤 나머지 50개로
확대한다.

1. 질문/required/preferred를 읽는다.
2. 문서에 표시된 수집 가격/재고/색상/사이즈와 후보 URL을 확인한다.
3. 후보별로 `적합`, `애매`, `부적합` 중 하나를 선택한다.
4. 질문별로 `A / 옛 검색`, `B / 새 검색`, `비슷하다` 중 하나를 선택한다.
5. 판단이 어려운 이유나 수집 정보 오류는 판단 메모에 기록한다.
6. 정답 없음 질문에서 두 검색이 모두 올바르게 0건이면 `비슷하다`로 기록한다.

판정 뜻은 다음과 같다.

- `적합`: 필수 조건을 모두 만족하고 질문 의도에도 맞는 근거가 충분하다.
- `애매`: 필수 조건은 만족하지만 용도나 스타일처럼 판단 근거가 부족하다.
- `부적합`: 필수 조건을 어기거나 명백히 다른 상품이다.

첫 10개에서 평가 기준이 이해 가능하고 서로 모순되지 않으면 나머지 50개를 검토한다.
Top 3 변경 19개와 0건 복구 7개는 반드시 사람이 확인한다. relevance를 수정하면 같은
명령을 다시 실행해 자동 지표도 갱신한다.

## 6. 실행과 산출물

```bash
make retrieval-ab-report
```

실행할 때마다 아래 임시 보고서가 생성된다.

- `services/product-backend/build/reports/retrieval-ab/summary.json`
- `services/product-backend/build/reports/retrieval-ab/human-review.csv`
- `services/product-backend/build/reports/retrieval-ab/human-review-first10.md`

검토 기준점으로 저장소에 고정한 DRAFT 결과는 아래 파일이다.

- `knowledge/eval/reports/retrieval-ab-v1-summary.json`
- `knowledge/eval/reviews/retrieval-ab-v1-first10-human-review.md`
- `knowledge/eval/reviews/retrieval-ab-v1-human-review.csv`

## 7. 운영 채택 기준

B를 A보다 개선된 검색으로 채택하려면 다음 조건을 모두 만족해야 한다.

- 필수 조건 위반율@3이 0%다.
- 정답 없음 정확도가 A보다 낮아지지 않는다.
- Recall@20과 nDCG@3 중 하나 이상이 개선되고 다른 하나가 낮아지지 않는다.
- 사람 검토에서 FTS 선호가 baseline 선호보다 많다.
- 0건 복구 후보가 사람 판정에서 `적합` 또는 `애매`다.
- p95 검색 시간이 1초 미만이다.

## 8. 현재 한계와 다음 평가

- 상품 20개와 질문 60개로 구성된 작은 신발 DRAFT data다.
- 질문과 relevance를 사람이 아직 검토하지 않았다.
- 현재 CSV는 탐색용으로 baseline/FTS 이름을 공개하므로 최종 대외 평가 전에는 variant를
  가린 별도 검토표를 사용해야 한다.
- 실제 사용자 traffic과 전체 판매처 분포를 대표하지 않는다.
- 사람 검토가 끝난 뒤 최소 200개 이상의 고정 상품 snapshot으로 확대한다.
- 확대 data에서 A/B를 다시 고정한 뒤 BGE-M3 vector를 C 비교군으로 추가한다.
