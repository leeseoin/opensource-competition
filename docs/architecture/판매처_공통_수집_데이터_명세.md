# 판매처 공통 수집 데이터 명세

- 작성일: 2026-07-20
- 문서 상태: v1 설계 초안
- 적용 대상: ABC마트, 29CM 및 이후 추가할 판매처

## 1. 목적

판매처마다 상품 데이터의 이름과 응답 형식이 다르다.

예를 들어 ABC마트는 상품명을 `PRDT_NAME`으로 제공하고, 29CM는 `productName`으로 제공한다. Go Collector는 이 차이를 판매처별로 해석한 뒤 모든 결과를 동일한 공통 형식으로 반환해야 한다.

```text
ABC마트 JSON ─┐
              ├→ Go Collector → 공통 SearchResult → Product Backend → PostgreSQL
29CM JSON ────┘
```

이 문서는 다음 내용을 정한다.

1. 검색할 때 공통으로 가져올 데이터
2. 후보 상품만 추가로 가져올 상세정보
3. 최종 후보만 가져올 리뷰 정보
4. 판매처 데이터와 공통 필드의 연결 기준
5. 현재 계약에서 보완해야 할 항목

## 2. 수집 원칙

- 검색된 모든 상품의 상세정보와 리뷰를 한 번에 수집하지 않는다.
- 검색 목록, 후보 상세, 최종 후보 리뷰의 세 단계로 나눈다.
- 판매처가 제공하지 않은 값은 추측하지 않고 `null`, 빈 배열 또는 `unknown`으로 기록한다.
- 가격·재고·옵션에는 출처 URL, 수집 시각, Collector 버전을 연결한다.
- 정확한 재고 수량보다 구매 가능 여부를 우선 저장한다.
- 리뷰 작성자 이름·프로필 등 식별정보는 저장하지 않는다.
- 리뷰 이미지는 내려받지 않고 사진 존재 여부만 저장한다.
- 판매처 전용 값은 공통 필드로 만들 필요가 있을 때만 승격하고, 그전에는 선택 속성으로 관리한다.

## 3. 단계별 수집 흐름

```text
1단계: 상품 검색
  → 판매처별 상품 목록 30개 안팎 수집
  → 가격·카테고리·기본 재고 조건으로 후보 축소

2단계: 후보 상품 상세
  → 후보 3~5개의 옵션·배송·소재·실측 수집

3단계: 최종 후보 리뷰
  → 최종 후보의 공개 리뷰만 제한된 범위에서 수집
  → Product Backend가 저장/비교/분석
```

ABC마트처럼 검색 JSON에 사이즈별 재고가 이미 포함된 경우에는 검색 단계에서 옵션도 함께 수집할 수 있다.

## 4. 검색 작업 공통 정보

검색 작업 정보는 상품이 어떤 조건으로 수집됐는지 재현하기 위해 필요하다.

| 필드 | 필수 여부 | 설명 | 현재 상태 |
|---|---|---|---|
| `requestId` | 필수 | 우리 시스템의 요청 식별자 | 구현 |
| `merchant` | 필수 | `abcmart`, `29cm`와 같은 판매처 식별자 | 구현 |
| `query` | 필수 | 사용자가 입력한 검색어 | 요청에만 구현, 응답 추가 예정 |
| `page` | 필수 | 수집한 페이지 번호 | 예정 |
| `pageSize` | 필수 | 요청한 페이지당 상품 수 | 예정 |
| `totalCount` | 선택 | 판매처가 알려준 전체 검색 결과 수 | ABC마트·29CM 구현, 미제공·실패 시 `null` |
| `hasNext` | 선택 | 판매처 검색 결과의 다음 페이지 존재 여부 | ABC마트·29CM 구현, 미제공·실패 시 `null` |
| `sort` | 필수 | 실제 적용한 정렬 기준 | 예정 |
| `appliedFilters` | 필수 | 실제 적용한 가격·사이즈·재고 필터 | 응답 추가 예정 |
| `collectedAt` | 필수 | 수집 시각 | 구현 |
| `collectorVersion` | 필수 | 판매처 Collector 버전 | 구현 |
| `status` | 필수 | 성공·부분 성공·차단·일시 오류 상태 | 구현 |
| `warnings` | 필수 | 일부 누락이나 불확실성 | 구현 |
| `errors` | 필수 | 수집 실패 정보 | 구현 |

## 5. 상품 검색 목록 공통 정보

### 5.1 상품 식별 정보

| 필드 | 필수 여부 | 설명 | 값이 없을 때 |
|---|---|---|---|
| `externalId` | 필수 | 판매처 상품 번호 | 상품 제외 및 경고 |
| `name` | 필수 | 상품명 | 상품 제외 및 경고 |
| `brand` | 선택 | 브랜드명 | `null` |
| `categoryPath` | 선택 | 대분류부터 소분류까지의 경로 | 빈 배열 |
| `productUrl` | 필수 | 사람이 다시 확인할 상품 주소 | 상품 제외 및 경고 |
| `imageUrls` | 선택 | 원본을 내려받지 않는 이미지 URL 목록 | 빈 배열 |

### 5.2 가격 정보

| 필드 | 필수 여부 | 설명 | 값이 없을 때 |
|---|---|---|---|
| `saleAmount` | 선택 | 현재 화면에 표시되는 실제 판매 가격 | `null` |
| `originalAmount` | 선택 | 할인 전 정상 가격 | `null` |
| `discountRate` | 선택 | 할인율 | `null` |
| `currency` | 가격 존재 시 필수 | `KRW`와 같은 통화 코드 | 가격 전체 `null` |
| `provenance` | 가격 존재 시 필수 | 가격 출처와 수집 시각 | 가격 전체 `null` |

판매처가 여러 가격을 제공하면 실제 화면에서 사용자가 보는 결제 기준 가격을 `saleAmount`에 연결한다. 의미가 불명확하면 임의로 선택하지 않고 화면과 대조한 후 매핑한다.

### 5.3 상품 상태와 요약 정보

| 필드 | 필수 여부 | 설명 | 값이 없을 때 |
|---|---|---|---|
| `stockStatus` | 필수 | `available`, `out_of_stock`, `unknown` | `unknown` |
| `saleStatus` | 선택 | 판매 중·출시 예정·판매 종료 | `null` |
| `rating` | 선택 | 0~5로 정규화한 평균 평점 | `null` |
| `reviewCount` | 선택 | 공개 리뷰 개수 | `null` |
| `gender` | 선택 | 남성·여성·공용·키즈 | `null` |
| `colors` | 선택 | 검색 단계에서 확인 가능한 대표 색상 | 빈 배열 |
| `modelCode` | 선택 | 판매처 스타일·모델 번호 | `null` |

`reviewCount: 0`은 리뷰가 없다는 뜻이고, `reviewCount: null`은 판매처가 검색 단계에서 리뷰 수를 제공하지 않았다는 뜻이다.

## 6. 옵션 공통 정보

| 필드 | 필수 여부 | 설명 |
|---|---|---|
| `externalId` | 선택 | 판매처 옵션 번호 |
| `label` | 필수 | 사용자에게 보여줄 옵션 이름 |
| `size` | 선택 | 정규화한 사이즈 |
| `color` | 선택 | 정규화한 색상 |
| `stockStatus` | 필수 | `available`, `out_of_stock`, `unknown` |
| `price` | 선택 | 옵션에 따라 가격이 다를 때의 가격 |
| `provenance` | 필수 | 옵션 출처와 수집 시각 |

ABC마트 `SIZE_LIST` 예시는 다음처럼 해석한다.

```json
{
  "250": "0",
  "255": "27",
  "270": "10"
}
```

```text
250 → out_of_stock
255 → available
270 → available
```

공개 응답에 정확한 재고 수량이 있어도 기본 공통 계약에는 수량을 저장하지 않는다. 재고 값이 0보다 큰지 확인해 구매 가능 여부로 변환한다.

## 8. 상품 상세정보

후보 상품에 대해서만 다음 정보를 추가로 수집한다.

| 필드 | 필수 여부 | 설명 |
|---|---|---|
| `description` | 선택 | 상품 상세 설명 |
| `materials` | 선택 | 소재 목록 |
| `countryOfOrigin` | 선택 | 제조국 |
| `manufacturer` | 선택 | 제조사 |
| `measurements` | 선택 | 굽 높이, 총장 등 값·단위·출처 |
| `attributes` | 선택 | 아직 공통 필드로 승격하지 않은 판매처 전용 속성 |

상품명·가격·재고처럼 공통 필드가 이미 있는 값은 `attributes`에 중복 저장하지 않는다.

## 9. 리뷰 공통 정보

최종 비교 후보에 대해서만 공개 리뷰를 제한된 범위에서 수집한다.

| 필드 | 필수 여부 | 설명 |
|---|---|---|
| `externalId` | 선택 | 판매처 리뷰 번호 |
| `rating` | 선택 | 0~5로 정규화한 리뷰 평점 |
| `text` | 선택 | 리뷰 본문 |
| `hasImage` | 필수 | 사진 리뷰 여부 |
| `purchasedOption` | 선택 | 공개된 구매 사이즈·색상 |
| `createdAt` | 선택 | 작성일 |
| `provenance` | 필수 | 리뷰 공개 출처와 수집 시각 |

다음 정보는 수집·저장하지 않는다.

- 리뷰 작성자 이름과 닉네임
- 작성자 프로필과 계정 식별자
- 리뷰 이미지 원본 파일
- 로그인해야 볼 수 있는 작성자 정보

## 10. 판매처별 검색 데이터 매핑

### 10.1 ABC마트

2026-07-20 공개 검색 화면의 Network 응답에서 `/display/search-word/result-total/list` JSON을 확인하고, 기존 HTML 파서를 이 JSON 방식으로 교체했다. 현재 상품 기본정보·카테고리·사이즈별 재고·리뷰 수·`totalCount`·`hasNext`를 공통 결과로 변환한다.

| ABC마트 JSON | 공통 필드 |
|---|---|
| `PRDT_NO` | `externalId` |
| `PRDT_NAME` | `name` |
| `BRAND_NAME` | `brand` |
| `CTGR_NAME_ALL` | `categoryPath` |
| `PRDT_IMAGE_URL` | `imageUrls[0]` |
| `PRDT_DC_PRICE` | `price.saleAmount` |
| `NRMAL_AMT` | `price.originalAmount` |
| `DISCOUNT_RATE` | `price.discountRate` |
| `SOLD_OUT` | `stockStatus` |
| `RVW_COUNT` | `reviewCount` |
| `GENDER_GBN_NAME` | `gender` |
| `COLOR_ID` | `colors[0]` |
| `STYLE_INFO` | `modelCode` |
| `SIZE_LIST` | `options` |
| `SEARCH_COUNT` | `totalCount` |
| `PAGE.finalPageNo` | 페이지 정보 |

### 10.2 29CM

현재 Go 구현은 공개 검색 화면이 호출하는 JSON 응답을 공통 상품으로 변환한다. 상품 기본정보/가격/품절 여부/카테고리/평점/리뷰 수는 구현됐고, 옵션/배송/리뷰 본문은 아직 구현 전이다. 가격은 쿠폰 적용 가능 표시값인 `displayPrice`가 아니라 기본 판매가인 `sellPrice`를 우선 사용한다.

| 29CM JSON | 공통 필드 |
|---|---|
| `itemId` | `externalId` |
| `itemInfo.productName` | `name` |
| `itemInfo.brandName` | `brand` |
| `itemInfo.thumbnailUrl` | `imageUrls[0]` |
| `itemInfo.sellPrice` | `price.amount` |
| `itemInfo.originalPrice` | 교차 검증의 정상가 비교 값 |
| `itemInfo.saleRate` | 교차 검증의 할인율 비교 값 |
| `itemInfo.isSoldOut` | `stockStatus` |
| `itemInfo.reviewScore` | `rating` |
| `itemInfo.reviewCount` | `reviewCount` |
| 카테고리 이벤트 속성 | `categoryPath` |

### 10.3 JSON/HTML 교차 검증

판매처 검색 JSON은 DB에 저장할 기본값이다. ABC마트는 같은 검색 화면을 시스템 Chrome으로
렌더링한 HTML 상품 카드와 비교하고, 29CM는 각 상품의 공개 상세 HTML 안 Product
JSON-LD와 비교한다. 비교 대상은 상품명/브랜드/판매가/정상가/할인율/이미지 URL/상품
URL이며 판매처 응답에 없는 값은 억지로 비교하지 않는다.

검증 결과는 상품의 선택 필드인 `verification`에 넣는다.

- `status`: `PENDING`, `MATCHED`, `MISMATCH`, `MISSING_IN_HTML`,
  `MISSING_IN_JSON`, `FAILED`
- `differences`: JSON 값과 HTML 값을 함께 기록한 차이 목록
- `jsonSourceUrl`, `htmlSourceUrl`, `checkedAt`: 검증 근거
- 원본 파일: `output/raw_json/{merchant}`와 `output/raw_html/{merchant}`
