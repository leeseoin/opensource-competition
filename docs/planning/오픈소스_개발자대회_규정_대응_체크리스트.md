# 오픈소스 개발자대회 규정 대응 체크리스트

작성일: 2026-07-19
상태: 개발 이후 확인할 제출 준비 항목

## 1. 이 문서의 목적

이 문서는 현재 개발을 멈추기 위한 규칙이 아니라, 대회 제출 전에 빠뜨리면 안 되는 항목을 보관하는 체크리스트다.

기능 개발은 [구현 TODO](Purchase_Research_Agent_TODO.md)를 기준으로 계속 진행한다. 라이선스 선정, 외부 구성요소 고지, 참가 자격 확인 등은 제출 준비 단계에서 이 문서를 기준으로 확인한다.

기준 자료: [2026년 오픈소스 개발자대회 운영규정](https://api.osscontest.kr/static/uploads/b3b4491a-3bbe-454e-a1d8-6ed475b01b14.pdf)

## 2. 현재 판단

| 항목 | 현재 상태 | 판단 |
|---|---|---|
| GitHub 저장소 공개 | 충족 | 현재 저장소는 Public이다. |
| 직접 작성한 코드의 오픈소스 라이선스 | 미충족 | 저장소 루트에 `LICENSE`가 없다. 제출 전 OSI 승인 라이선스를 선택해야 한다. |
| 외부 라이브러리와 모델 출처 및 라이선스 | 초안 공개 | 운영규정 5쪽 제8조 제5항과 6쪽 제8조 제6항을 근거로 `THIRD_PARTY_NOTICES.md`를 공개했다. 규정이 이 파일명을 지정한 것은 아니다. |
| Codex와 Claude를 이용한 개발 | 사용 내역 공개 | 운영규정 7쪽 제9조 제5항은 개발 보조 사용을 허용한다. 규정이 별도 파일을 요구한 것은 아니지만 검토 방법을 `AI_USAGE.md`에 공개했다. |
| MCP/Agent/Plugin에서 외부 AI 사용 | 확인 필요 | 프로젝트 성격상 예외 항목에 해당할 가능성이 있으나 최종 실행 구조를 기준으로 주최 측에 서면 확인하는 것이 안전하다. |
| 로컬 공개 가중치 모델 실행 | planned | Ollama, llama.cpp, GPU 모델 서버 Adapter는 구현 계획에 포함되어 있다. |
| 판매처 공개 정보 수집 | 주의 필요 | 대회 규정 외에도 판매처 약관, robots 정책, 저작권, 개인정보 기준을 지켜야 한다. |
| 정부 지원·중복 수상·중복 참가 | 확인 필요 | 코드로 판단할 수 없으므로 팀원이 직접 확인해야 한다. |

현재까지 확인한 범위에서는 즉시 개발을 중단할 결격 사유가 발견되지 않았다. 다만 이 판단은 법률 자문이 아니라 운영규정과 저장소 상태를 비교한 결과다.

## 3. 제출 전 필수 체크리스트

### 저장소와 라이선스

- [ ] 팀과 상의해 MIT, Apache-2.0 등 OSI 승인 라이선스를 선택한다.
- [ ] 저장소 루트에 `LICENSE`를 추가한다.
- [ ] README에 프로젝트 라이선스를 표시한다.
- [ ] 직접 작성한 전체 제출 소스가 공개 저장소에서 확인되는지 점검한다.
- [ ] 수상 시 저장소를 5년 동안 공개해야 한다는 조건을 팀과 공유한다.

### 외부 코드/도구/model

- [x] 운영규정 5쪽 제8조 제5항과 6쪽 제8조 제6항의 공개 의무를 근거로 `THIRD_PARTY_NOTICES.md` 초안을 작성한다. 운영규정이 이 파일명과 형식을 직접 요구한 것은 아니라는 점도 문서에 표시한다.
- [x] PostgreSQL 16 bundled `pg_trgm`의 공식 출처, 라이선스와 상품 검색 사용 범위를 `THIRD_PARTY_NOTICES.md`에 기록한다.
- [x] pgvector 0.8.2와 선택적 BGE-M3/Ollama adapter의 출처, license, 실행 위치, 전송 data와 weight 미포함 상태를 공개 문서에 기록한다.
- [ ] 제출 시점에 Go, Spring Boot, Next.js, MCP Server 및 Plugin에서 실제 사용하는 직접/간접 의존성 전체 목록을 다시 생성한다.
- [ ] Ollama, llama.cpp 및 공개 가중치 모델의 라이선스와 상업적·재배포 조건을 확인한다.
- [ ] 외부 코드나 예제를 참고한 부분은 원본 URL과 라이선스를 기록한다.
- [x] manifest와 AI integration 변경에 공개 문서 갱신이 빠지면 실패하는 `make docs-check`와 GitHub Actions 검사를 추가한다.

### AI 사용

- [x] 운영규정 7쪽 제9조 제5항을 근거로 `AI_USAGE.md`에 Codex와 Claude Code의 개발 보조 범위 및 사람의 검토 방법을 공개한다. 운영규정이 이 파일을 직접 요구하지 않는다는 점도 문서에 표시한다.
- [ ] 팀원이 AI가 생성하거나 수정한 주요 코드를 직접 설명할 수 있는지 확인한다.
- [ ] 최종 실행에 사용하는 모델명, 제공자, 가중치 공개 여부, 라이선스, 실행 방식을 제출 양식에 기록한다.
- [ ] BGE-M3를 최종 경로로 채택하면 Ollama manifest digest, 양자화 artifact license와 한국어 검색 품질 평가 결과를 확정한다.
- [ ] Codex·Claude 외부 연결이 MCP·Agent 통합 예외에 해당하는지 주최 측에 문의하고 답변을 보관한다.
- [ ] 가능하면 Ollama 또는 llama.cpp를 이용한 로컬 실행 경로 하나를 실제로 검증한다.

### 판매처 데이터 수집

- [ ] 판매처별 이용약관과 robots 정책을 제출 시점에 다시 확인한다.
- [ ] 로그인, CAPTCHA, 접근 통제, 요청 제한을 우회하는 기능이 없는지 점검한다.
- [ ] 실제 판매처 smoke test는 opt-in으로 유지하고 기본 CI에서는 저장된 fixture를 사용한다.
- [ ] 판매처별 요청 간격, 동시 Worker 수, timeout, retry 상한을 기록한다.
- [ ] 리뷰 작성자 이름·프로필 등 식별정보가 DB에 저장되지 않는지 테스트한다.
- [ ] 상품 이미지와 리뷰 이미지를 불필요하게 복제·재배포하지 않는지 확인한다.

### 참가 자격과 중복 지원

- [ ] 참가자 국적과 학생부·일반부 구분을 확인한다.
- [ ] 한 사람이 다른 팀 또는 다른 부문에 중복 참가하지 않았는지 확인한다.
- [ ] 같은 프로젝트로 정부·공공기관의 지원이나 수상을 받은 이력이 있는지 확인한다.
- [ ] 대회 기간 중 정부 지원을 받으면 규정에 정한 기간 안에 주최 측에 알린다.
- [ ] 팀원별 담당 업무와 실제 기여 내용을 정리한다.

## 4. 당장 하지 않는 작업

다음 작업은 현재 Collector와 Backend 기능 개발보다 우선하지 않는다.

- 라이선스 최종 선택
- 제출 양식 작성
- 외부 구성요소 전체 목록 확정
- AI 모델 공개 양식 작성 **(제출 환경의 Claude Code CLI 실제 model ID 확인 후 반영 필요)**
- 주최 측 질의 발송

단, 새로운 라이브러리, model 및 외부 코드를 추가할 때는 같은 commit에서 `THIRD_PARTY_NOTICES.md`를 갱신한다. AI 개발 보조와 runtime AI 변경은 `AI_USAGE.md`도 갱신한다. `AGENTS.md` 규칙과 `make docs-check`가 누락을 검사하지만 출처 및 license의 정확성은 사람이 공식 자료로 확인한다.

## 5. 완료 기준

이 문서의 모든 필수 항목이 체크되고, 관련 증거 파일과 주최 측 답변을 저장소 또는 팀 공유 공간에서 확인할 수 있으면 대회 규정 대응을 완료로 본다.
