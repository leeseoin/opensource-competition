## 배경과 범위

사용자가 `갈색 구두 찾아줘`라고 명시했는데 Codex가 색상을 기본 preferred로 구조화해
검정 상품을 조건 완화 후보로 반환했다. 단정한 색상 요청과 선호 표현을 구분하도록 Web
Agent Gateway의 조건 강도 보정을 추가했다.

## 구현 내용

- `frontend/purchase-web/app/lib/codex-runtime.ts:155` `isSoftColorPreference`: 질문에서 해당
  색상 주변의 `이면 좋겠어`/`선호`/`가능하면` 등 완화 표현 판정
- `frontend/purchase-web/app/lib/codex-runtime.ts:169` `normalizePurchaseCondition`: 단정한
  색상은 required, 완화 색상만 preferred로 결정적 보정
- `frontend/purchase-web/app/lib/codex-runtime.test.ts:116`
  `사용자 색상 표현의 필수와 선호 강도를 구분한다`: 반대 방향의 LLM 출력을 모두 보정

## 발생 문제와 원인

Codex prompt가 색상을 기본 preferred로 지정했다. 따라서 Backend는 설계대로 색상
MISMATCH를 선호 완화로 표시했지만 사용자의 실제 구매 불가능 조건을 위반했다.

## 해결

명시 색상은 기본 required로 바꾸고 색상 주변에 완화 표현이 있을 때만 preferred로 둔다.
Backend의 기존 required 색상 SQL 필터가 적용되므로 불일치와 색상 정보 없음 상품은 모두
후보에서 제외된다.
