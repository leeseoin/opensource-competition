# 2026-08-10 QUEUE-002 실제 판매처 Queue E2E와 RUNNING 상태

- 기능 ID: `QUEUE-002`
- 구현 commit: `3ff397c`, `523ba3f`
- 기록 상태: 버그 수정 기록/구현 기록

## 배경과 범위

Spring Boot가 값이 없는 가격 필터를 JSON `null`로 발행해 Python Worker의 공유 Schema
검증을 통과하지 못했다. 빈 선택 필터를 생략하도록 Queue 직렬화 계약을 정렬하고,
ABC마트 실제 검색부터 RabbitMQ, Python Worker, Spring Boot 결과 소비와 PostgreSQL
저장까지 수직 흐름을 검증했다.

Spring Boot가 Worker의 시작 이벤트를 소비해 `collection_tasks`와 `collection_jobs`를
`RUNNING`으로 저장하고 API에 실행 중 작업 수를 노출하는 상태 전이를 추가했다.

## 발생 문제와 원인

- 증상: 최소 Swagger 입력으로 등록한 ABC마트 작업이 검색 Queue에서 사라진 뒤
  `QUEUED`에 머물렀다.
- 원인: Java record의 선택적 Integer 필드가 기본 Jackson 직렬화에서 `null`로 포함됐고,
  공유 CollectionTask Schema는 필드가 존재할 경우 integer만 허용했다.
- 증상: Worker가 실제 판매처를 수집 중이어도 job 조회는 `QUEUED`를 반환했다.
- 원인: Spring Boot가 작업 시작 이벤트를 받지 않고 최종 결과만 소비했다.

## 해결

`SearchFilters`에 non-null 직렬화 규칙을 적용했다. 가격 제한을 지정하지 않았다는 의미는
필드 누락으로 표현하고, 숫자가 주어진 경우에만 기존 integer 계약으로 발행한다.

Spring은 `running` 결과를 상품 저장 경로와 분리해 시작 시각과 상태만 기록한다. 중복 또는
최종 결과 뒤 늦게 도착한 시작 이벤트는 완료 상태를 되돌리지 않는다.
