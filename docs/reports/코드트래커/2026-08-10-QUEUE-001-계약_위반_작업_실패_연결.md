## 배경과 범위

Python Worker가 식별 가능한 CollectionTask 계약 위반 메시지를 검색 DLQ로 보냈지만
Spring Boot에는 결과를 발행하지 않아 `collection_jobs`와 `collection_tasks`가 계속
`QUEUED`로 남았다. 원본 메시지의 DLQ 보존과 작업 상태 종결을 함께 보장하도록
실패 결과 연결을 추가했다.

## 구현 내용

- `purchase-research-agent/app/messaging/contracts.py:118`
  `extract_collection_task_identity`: 계약 위반 JSON에서 형식이 안전한 `taskId`와
  `jobId`만 제한적으로 복구
- `purchase-research-agent/app/messaging/rabbitmq.py:54` `decide_message`: 식별 가능한 계약

  `COLLECTION_TASK_CONTRACT_INVALID` 비재시도 실패 결과 생성 및 결과 계약 검증

## 발생 문제와 원인

- 증상: Swagger에서 등록한 작업이 Worker 소비 뒤에도 계속 `QUEUED`였다.
- 원인: `priceMin`과 `priceMax`의 JSON `null`이 CollectionTask Schema의 integer 계약을
  위반했고, Python Worker가 원본을 DLQ로만 이동해 Spring Boot가 실패 상태를 알 수
  없었다.

## 해결

계약 전체를 신뢰하지 않고 형식이 제한된 작업 식별자만 복구한다. 복구에 성공하면 유효한
실패 결과를 결과 Queue에 publisher confirm으로 발행한 뒤 원본을 reject한다. 식별할 수
없는 JSON은 잘못된 작업과 임의 DB 작업을 연결하지 않도록 결과를 만들지 않고 DLQ에만
보존한다.
