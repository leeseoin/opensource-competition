## 배경과 범위

ABC마트/29CM 공개 검색을 Python과 Go가 같은 비교 Contract로 최대 10,000개까지
수집할 수 있는지 검증했다. 운영 Java Backend/MCP 경계는 바꾸지 않았고 대량 결과는
`tmp/`에만 저장했다.

## 발생 문제와 원인

- ABC마트는 검색어 10개 사이 중복률이 54.56%여서 최대 9,417개에서 검색어가 끝났다.
- Python 재개 요약은 고유 수는 누적하면서 Contract 통과/누락 필드는 새 구간만 표시했다.
- Python 공통 HTTP client의 29CM Origin/Referer가 ABC마트 요청에도 들어갔다.
- 실제 수집 wall time은 1초 요청 간격과 네트워크가 대부분이라 언어 parser 성능을
  직접 설명하지 못했다.
- Python은 원가/할인율/style code를 비교 계약에 직접 옮기지만 Go 운영 모델에는 일부
  필드가 없어 누락 필드 수가 달랐다.

## 해결

- 고유 상품 목표와 별도로 요청 예산/검색어 소진을 안전 종료 조건으로 두고 9,417개를
  실제 결과로 기록했다.
- checkpoint에 누적 통계를 저장하고 이전 checkpoint는 gzip 결과에서 복원했다.
- 29CM 전용 Origin/Referer를 해당 Adapter 요청에만 설정했다.
- 실수집 E2E와 동일 저장 fixture parser benchmark를 분리했다.
- Go 비교 Adapter는 운영 계약에 없는 사실을 만들지 않고 빈 값/null과 누락 통계로
  표현했다.
