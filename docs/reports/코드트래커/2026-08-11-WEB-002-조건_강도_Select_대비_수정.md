# 2026-08-11 WEB-002 조건 강도와 Select 대비 수정

- 기능 ID: `WEB-002`
- 구현 commit: `b392bd2`, `3524655`
- 기록 상태: 버그 수정 기록

## 배경과 범위

사용자가 조건 확인 화면에서 `갈색/필수`를 `검정`으로 교체하면 강도가 `선호`로
바뀌었고, Radix Select 목록 항목은 hover 시 글자가 보이지 않았다. 기존 조건 강도
보존과 Portal 목록의 시각 대비를 수정했다.

## 구현 내용

- `frontend/purchase-web/app/lib/condition-editing.ts:4` `parsePrioritizedList`: 새 목록 값이
  기존 조건 묶음의 첫 강도를 이어받고 기존 값은 개별 강도를 유지
- `frontend/purchase-web/app/chat/chat-experience.tsx:195` `updateListCondition`: 색상/사이즈/
  용도/중요 조건 편집을 공통 강도 보존 함수에 연결
- `frontend/purchase-web/app/components/ui/app-select.module.css:1` `.trigger, .content`:
  Portal에서도 사용할 Select 전용 색상 fallback과 hover/checked 대비 보장
- `frontend/purchase-web/app/lib/product-candidates.test.ts:114`
  `목록 값을 교체할 때 기존 조건 강도를 유지한다`: 갈색/필수에서 검정/필수로 교체되는
  회귀 경로 검증

## 발생 문제와 원인

- 값 교체 문제: 기존 구현은 문자열이 완전히 같은 조건만 강도를 보존하고 새 문자열에는
  필드 fallback을 사용했다. 따라서 `갈색`을 `검정`으로 바꾸면 같은 조건 묶음의 필수
  강도를 잃었다.
- hover 문제: Select 목록은 Radix Portal을 통해 화면 `.page` 바깥에 렌더링되지만
  `--blue`/`--lime`/`--ink`/`--paper` 변수는 `.page` 안에만 존재했다. hover 글자색은
  흰색으로 바뀌고 배경색 선언은 무효가 되어 흰 배경에서 글자가 보이지 않았다.

## 해결

새 값은 무조건 필수로 바꾸지 않고 기존 조건 묶음의 강도를 상속한다. Select trigger와
Portal content에는 프로젝트 테마 변수가 없을 때 사용할 동일 색상 fallback을 둬 모든
렌더링 위치에서 배경과 글자 대비를 함께 적용한다.
