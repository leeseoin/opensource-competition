## 배경과 범위

수집 작업 등록 API가 `jobId`를 반환해도 이전에는 RabbitMQ 내부 처리 여부와 최종 상품
수를 API에서 확인할 수 없었다. 이번 구현은 Queue 발행 전 job과 페이지 작업을
PostgreSQL에 만들고, 결과 소비 시 최종 상태, 상품 수, 소요시간 및 JSON/HTML 검증
집계를 저장하는 범위다.

## 발생 문제와 원인

- migration 이전에 만든 Queue 결과는 대응하는 `collection_tasks` 행이 없어 상태를 연결할
  수 없었다. 이는 상품 저장과 Queue 처리가 작업 상태 저장보다 먼저 구현됐기 때문이다.
- 상태 갱신이 `taskId`만 사용하면 다른 `jobId`가 포함된 결과도 같은 작업에 연결될 수
  있었다. 기존 의미 검증은 `taskId`와 Collector `requestId`만 비교했다.

## 해결

새 작업은 발행 전에 job/task 상태를 먼저 저장한다. 과거 미추적 결과는 상품 저장 호환성을
유지하고 상태 갱신만 건너뛴다. 추적 중인 결과는 저장된 상위 job과 결과의 `jobId`를 함께
비교하며, 불일치하면 상품 저장과 상태 갱신 transaction 전체를 rollback한다.
