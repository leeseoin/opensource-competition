## 배경과 범위

후보 검색 뒤 모델이 상품 사실을 추측하지 않고 상세/근거/비교를 조회하며, DB 결과가
없거나 오래됐을 때만 수집을 요청하고 선택 상품을 구매 직전에 재검증할 수 있도록 MCP와
Product Backend API를 확장했다.

## 발생 문제와 원인

기존 MCP는 조사 세션과 후보 검색 세 도구만 있어 선택 상품의 실제 근거, 후보 비교와
최신성 판단을 모델이 구조화된 도구로 수행할 수 없었다.

## 해결

MCP는 저장소와 Queue에 직접 접근하지 않고 Product Backend REST API만 호출하도록 유지했다.
최신 데이터에는 불필요한 수집을 만들지 않고, 수집이 필요한 경우에도 최대 5개 검색
작업으로 제한했다.

## 검증

- `cd services/mcp-server && npm test`: backend client와 stdio 도구 4개 테스트 통과
- `ProductStorageIntegrationTests.returnsProductDetailEvidenceAndComparison`: 통과
- `CollectionRefreshServiceTests`: FRESH 생략과 STALE 수집 요청 통과
- 실제 REST E2E: 상품 상세/근거와 상품 2개 비교 반환 확인
- 실제 REST E2E: 최신 `구두` 데이터는 `FRESH/NO_ACTION` 반환 확인
