## 배경과 범위

Codex가 PostgreSQL이나 판매처를 직접 호출하지 않도록 Product Backend REST API만 연결하는
stdio MCP 서버를 구현했다. 이번 범위는 조사 세션 생성/사용자 확인/확정 조건 상품 후보
검색 도구까지이며 상품 상세 및 구매 전 재검증 도구는 포함하지 않는다.

## 구현 내용

- `services/mcp-server/src/index.ts:35` `main`: stdio MCP 서버와 조사 세션 도구 세 개 등록
- `services/mcp-server/src/index.ts:27` `toToolResult`: REST 응답을 MCP text 및 structured content로 변환
- `services/mcp-server/src/backend-client.ts:43` `ProductBackendClient`: Product Backend 전용 REST client와 10초 timeout 구현
- `services/mcp-server/src/mcp-smoke.test.ts:8` `stdio MCP 서버가 조사 세션 도구를 공개한다`: 실제 child process 초기화와 tool list 검증
- `.codex/config.toml:1` `mcp_servers.purchase_research`: 저장소 범위 Codex MCP 실행 설정
- `plugins/purchase-research-agent/.mcp.json:1` `purchase_research`: Plugin이 같은 MCP 서버를 실행하도록 설정

## 발생 문제와 원인

Node의 TypeScript strip-only 실행이 constructor parameter property를 지원하지 않았고 `.ts`
import 확장자가 NodeNext compiler 설정과 충돌했다. source 직접 실행과 TypeScript compiler의
module 해석 방식이 서로 달랐기 때문이다.

## 해결

MCP source와 테스트를 `tsc`로 먼저 빌드하고 `dist`의 JavaScript를 실행하도록 통일했다.
stdout은 MCP protocol에만 사용하고 Product Backend 주소는 환경 변수로 분리했다.
