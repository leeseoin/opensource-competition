## 발생 문제와 원인

- 증상: 조건 확인 뒤 DB 결과가 없으면 화면이 즉시 빈 결과로 끝났고, 별도 수집과 재검증
  진행 상태를 사용자가 확인할 수 없었다.
- 원인: 조사 세션과 collection job 및 verification 사이를 연결하는 영구 실행 상태가 없었다.
- 추가 문제: Web `package.json`의 테스트 대상 추가를 문서 검사가 의존성 변경으로 감지했다.
- 추가 문제: Agent Run transaction 안에서 Queue 메시지가 DB job commit보다 먼저 소비될 수
  있는 race를 검토 중 발견했다.
- 실제 조건부 수집 smoke test에서 `agent_run_collection_jobs`의 `run_id`가 JPA insert에
  두 번 포함돼 PostgreSQL parameter 오류가 발생했다.
- `dev-ls` 통합 시 기존 수집 요청 snapshot migration이 이미 V11을 사용해 Agent Run의
  V11 migration과 버전이 중복됐다.
- PR 리뷰에서 다중 판매처 중 뒤쪽 판매처의 Queue 발행이 실패하면 앞에서 접수된 작업이
  있어도 Agent Run 전체가 FAILED로 종료되는 부분 실패 처리를 확인했다.

## 해결

상태와 순서가 보장된 사건 및 수집 job 연결을 PostgreSQL에 저장했다. 같은 조사 세션과
동시 진행 요청은 행 잠금과 고유 제약으로 중복 실행을 막는다. 수집 요청 실패는 내부 오류
원문을 노출하지 않고 FAILED 실행으로 보존한다. Web과 MCP는 백그라운드 무한 thread 대신
호출 횟수와 시간이 제한된 진행 API를 사용한다. 새 package는 추가하지 않았으며
`THIRD_PARTY_NOTICES.md`에 테스트 명령만 변경됐음을 기록했다.
수집 job 등록과 발행 실패 기록은 독립 transaction으로 먼저 확정해 빠른 Worker도 job을
조회할 수 있게 했다.
복합키 entity는 `AgentRun` 연관 자체를 `@Id`로 매핑해 `run_id` column을 한 번만 쓰도록
수정하고 실제 MISSING 수집 시작 통합 테스트를 추가했다.
Agent Run migration은 기존 V11 뒤에 적용되도록 V12로 이동했다.
판매처별 발행 실패를 격리해 하나 이상의 job이 접수됐으면 `COLLECTING`과
`COLLECTION_PARTIAL` 사건으로 계속 진행하고, 접수된 job이 하나도 없을 때만 FAILED로
종료하도록 수정했다.
