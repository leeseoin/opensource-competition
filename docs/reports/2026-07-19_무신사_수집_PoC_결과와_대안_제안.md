# 무신사 수집 PoC 결과와 대안 제안 보고서

작성일: 2026-07-19

## 1. 결론

무신사 상품 검색 데이터는 기술적으로 가져오는 데 성공했다. 하지만 현재 우리 Collector는 무신사 `robots.txt`에서 허용된 Agent가 아니므로, 무신사를 대회용 주요 수집 사이트로 계속 사용하는 것은 위험 부담이 있다.

따라서 무신사 구현은 기술 검증용 PoC로 남기고, 실제 대회 시연과 이후 개발에서는 자동 수집 허용 범위가 더 명확한 다른 의류 사이트를 찾는 것이 좋다.

## 2. 무신사 수집이 어려웠던 이유

처음에는 무신사 상품 페이지가 SPA 방식이고 자동 수집 정책도 제한적이어서 일반적인 HTML 크롤링이 어렵다고 판단했다.

현재 [무신사 robots.txt](https://www.musinsa.com/robots.txt)는 일부 지정 Agent만 허용하고, 그 외 일반 Agent에는 전체 경로를 허용하지 않는 형태다.

```text
User-agent: 지정된 일부 Agent
Allow: /

User-agent: *
Disallow: /
```

우리 Collector는 무신사나 ChatGPT로 위장하지 않고 `PurchaseResearchAgent`라는 자체 User-Agent를 사용한다. 따라서 기술적으로 페이지 응답을 받을 수 있더라도 무신사가 일반 자동 수집을 허용했다고 볼 수는 없다.

또한 요청을 1초 간격으로 제한하는 것은 서버에 부담을 줄이기 위한 장치일 뿐, 허용되지 않은 수집을 허용된 수집으로 바꾸는 조건은 아니다.

## 3. 현재 구현한 방법

브라우저 자동화 도구나 접근 우회 기능은 사용하지 않았다. 로그인하지 않은 상태에서 공개 검색 페이지에 일반 HTTP 요청을 보내고, 응답 HTML 안의 초기 JSON을 읽는 방식으로 구현했다.

```text
무신사 검색 페이지 요청
→ HTML 응답
→ HTML의 __NEXT_DATA__ JSON 확인
→ 상품 목록 추출
→ Collector 공통 Product 형식으로 변환
```

현재 가져오는 정보는 다음과 같다.

- 상품번호
- 상품명
- 브랜드
- 가격
- 상품 URL
- 대표 이미지 URL
- 품절 여부
- 평점과 리뷰 수
- 수집 URL과 수집 시각

2026-07-19에는 `구두` 검색 결과 3개를 실제 JSON으로 반환하는 것을 확인했다.

현재 구현하지 않은 기능은 다음과 같다.

- 상품 상세 설명
- 사이즈·색상 옵션
- 옵션별 재고
- 배송 정보
- 리뷰 본문을 Collector 결과로 변환하는 기능
- PostgreSQL 저장

## 4. 사용하지 않은 방법

다음과 같은 우회 방식은 구현하지 않았다.

- User-Agent를 `ChatGPT-User` 등으로 위장
- 프록시나 IP 변경으로 차단 회피
- 로그인 쿠키와 세션 공유
- CAPTCHA 또는 접근 통제 우회
- 다른 사용자의 개인정보 저장

현재 코드는 자체 User-Agent, 요청 timeout, 응답 크기 제한, 최소 요청 간격을 적용한 소량 PoC다.

## 5. 대회 운영규정을 고려한 판단

[오픈소스 개발자대회 운영규정](https://api.osscontest.kr/static/uploads/b3b4491a-3bbe-454e-a1d8-6ed475b01b14.pdf)이 크롤링 자체를 금지하는 것은 아니다. 다만 참가자는 다른 서비스의 권리와 라이선스를 침해하지 않고 정상적인 대회 운영을 방해하지 않을 책임이 있다.

무신사는 우리 Collector의 자동 수집을 명확하게 허용한 상태가 아니다. 이 상황에서 무신사 상세·옵션·리뷰 수집량까지 늘리면 기술 구현보다 정책 설명과 심사 위험이 더 커질 수 있다.

대회의 핵심은 특정 쇼핑몰을 많이 크롤링하는 것이 아니라 다음 기능을 보여주는 것이다.

```text
판매처 데이터 수집
→ 공통 형식으로 정리
→ DB 저장
→ 리뷰 근거 분석
→ 상품 비교
→ 구매 전 가격·재고 재검증
```

따라서 무신사를 반드시 고집할 필요는 없다.

## 6. 제안

### 무신사

- 현재 검색 구현과 테스트는 기술 PoC 기록으로 남긴다.
- 저장된 fixture를 이용한 파서 테스트는 유지한다.
- 실제 무신사 요청은 기본 개발과 대회 시연에서 제외하는 방향을 검토한다.
- 공식 API, 공개 MCP, 제휴 Feed 또는 별도 허가를 확보하면 다시 활성화한다.

### 새로운 의류 사이트

무신사 대신 다음 조건을 만족하는 의류 사이트를 조사한다.

- 로그인 없이 상품 검색과 상세 정보를 볼 수 있음
- `robots.txt`에서 일반 Agent의 상품 경로 접근을 허용함
- 이용약관에서 자동 수집을 명시적으로 금지하지 않거나 별도 허가를 받을 수 있음
- 상품명, 가격, 옵션, 재고, 리뷰가 공개되어 있음
- 요청량을 작게 제한해도 PoC를 시연할 수 있음

후보 사이트를 정하기 전에 `robots.txt`, 이용약관, 공개 API·상품 Feed 제공 여부를 먼저 확인한다.

## 7. 다음 작업 제안

1. 무신사 live 요청을 기본 비활성화하는 방법을 결정한다.
2. 대체 의류 사이트 후보를 2~3개 조사한다.
3. 허용 범위가 가장 명확한 사이트 한 곳을 선택한다.
4. 선택한 사이트의 검색 Adapter를 추가한다.
5. 상품 검색 결과를 Python Backend와 PostgreSQL에 저장하는 흐름을 먼저 완성한다.
6. 이후 상세·옵션·리뷰 수집을 추가한다.

## 8. 최종 의견

무신사 PoC는 SPA 형태의 쇼핑몰에서도 HTML 안의 초기 JSON을 찾아 공통 상품 데이터로 변환할 수 있다는 기술 검증으로 의미가 있다.

하지만 대회 프로젝트에서는 기술적으로 가능한 것뿐 아니라 데이터 사용 근거를 설명할 수 있어야 한다. 따라서 무신사를 주요 수집 대상으로 확장하기보다 허용 범위가 명확한 다른 의류 사이트로 전환하는 것이 개발 속도와 대회 위험 관리 측면에서 더 적절하다.
