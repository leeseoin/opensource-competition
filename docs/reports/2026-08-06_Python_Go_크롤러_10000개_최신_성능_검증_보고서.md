# Python/Go 크롤러 10,000개 최신 성능 검증 보고서

작성일: 2026-08-06

## 결론

ABC마트에서는 두 언어가 같은 고유 상품 9,429개를 수집한 뒤 준비한 검색어 결과를 모두
소진했다. 29CM에서는 두 언어 모두 고유 상품 10,000개 목표에 도달했다. 네 실행 모두
Contract 실패, HTTP 오류와 429가 없었다.

의도적으로 요청 사이를 1초씩 기다리므로 전체 실행 시간은 언어보다 외부 응답과 요청 제한의
영향이 크다. wall 시간은 사실상 같았지만 Go는 Python보다 CPU 시간이 약 1.93배에서 2.35배
적었고 최대 메모리는 약 2.04배에서 2.15배 적었다.

## 동일 측정 조건

- 판매처: ABC마트/29CM
- 검색어 순서: 구두/운동화/스니커즈/러닝화/샌들/슬리퍼/부츠/신발/여성화/남성화
- 고유 상품 상한: 10,000개
- 페이지 크기: 50개
- 요청 예산: 500회
- 판매처 요청 간격: 최소 1초
- timeout: 15초
- 일시 오류 재시도: 최대 1회
- 중단 조건: 목표 도달/검색어 소진/요청 예산 소진/시간 소진/401/403/429
- 저장: 상품 ID 중복 제거, `v1-unified` Contract 검증, gzip NDJSON와 checkpoint

로그인, CAPTCHA, 접근 제한 우회는 사용하지 않았다. 네 실행은 동시에 돌리지 않고 하나씩
순서대로 실행했다.

## 측정 경계

이 수치는 공개 검색 JSON 요청부터 정규화, 공통 Contract 검증, 중복 제거와 압축 저장까지를
측정한다. 운영 API와 Worker가 수행하는 JSON/HTML 전수 검증은 제거하지 않았지만, 판매처별
검증 방식이 달라 검색 처리량 비교에서는 분리했다.

- ABC마트 운영 검증: 검색 JSON 한 페이지와 JavaScript rendering 검색 HTML 한 페이지 대조
- 29CM 운영 검증: 검색 JSON 상품과 각 상품 상세 HTML의 Product JSON-LD 대조

HTML 검증을 포함한 전체 운영 처리량은 별도 지표로 관리해야 한다. 특히 29CM은 상품 하나마다
상세 요청이 추가되므로 검색 pagination 처리량과 같은 숫자로 비교하면 안 된다.

## 해석

### 실제 수집 시간

ABC마트에서 Python이 약 1.67초 빨랐고 29CM에서는 Go가 약 0.61초 빨랐다. 전체 실행의
0.4%보다 작은 차이이므로 언어 우위로 해석하지 않는다. 외부 응답 시간과 1초 간격의 영향이
더 크다.

### CPU와 메모리

- ABC마트: Python CPU는 Go의 약 1.93배, 메모리는 약 2.15배다.
- 29CM: Python CPU는 Go의 약 2.35배, 메모리는 약 2.04배다.

운영 Worker를 Go로 유지한다는 현재 선택을 뒷받침하지만, 네트워크 수집 전체 시간을 크게 줄여
준다는 의미는 아니다. Python 구현은 새 판매처 구조 탐색, 빠른 실험과 결과 교차 검증에 계속
사용할 수 있다.

## 문제와 해결

첫 Go ABC마트 실행은 운영용 Searcher가 Chrome HTML 검증까지 수행해 첫 페이지 50개에 약
166초가 걸렸다. 실행을 중단하고 `sandbox/ls`의 `2d2e64f`에서 대량 비교용 Searcher를 별도로
만들었다. 운영 API와 Worker의 전수 검증은 유지했으며 비교 CLI만 검색 처리 성능 경계를
사용한다.
